## What it is

<!-- SF Symbol: app -->
Sift is a native macOS app that audits my installed apps with a local model —
what each app is, whether it earns its place in my workflow, what needs updating,
which licenses and subscriptions I pay for. The distinct thing: analysis is
grounded and local-first — evidence, not guesses, and nothing leaves the Mac by
default.

Built by **Kika** ([aka-kika](https://github.com/aka-kika)). The app I open to
decide what stays on my Mac.

## The milestone

<!-- SF Symbol: flag.checkered -->
The first release after going public, and the first one shaped by someone
else's good work. I tried [DuoUpdater](https://github.com/jizhi0v0/duo-updater),
found it excellent, and asked what Sift could learn from it. Not the install
engine — that is a different product — but the ideas around it: GitHub as a
place updates live, what an app is built with, and what a version number
actually means.

## What shipped in 1.12.0

<!-- SF Symbol: shippingbox -->
- **GitHub releases as a fourth update source** — when the link saved for an app is a GitHub repo, that repo's latest release answers. Direct-download apps stop reading as "unavailable". No drafts, no betas, no `nightly` tags, and a Mac App Store copy is never answered by GitHub.
- **No rate limit to run into** — the check reads the redirect of the repo's `/releases/latest` page instead of calling `api.github.com`. Measured first: without a token, even a `304` spends one of the API's 60 requests an hour.
- **Open app to update** — for an app with its own Sparkle updater, the button opens the app so it installs the update in place. No more downloading a copy and swapping it in by hand; the download stays as a quieter second button.
- **Built with** — a new fact under every analysis: Electron, Tauri, Flutter, Qt, Java, Chromium, Mac Catalyst, or native (SwiftUI / AppKit). Read from the bundle alone; the model gets the same fact.
- **Build-number updates** — a Sparkle app that ships a new build under the same version (`1.0` build 374 to 390) is found, and shown as `1.0 (390)`.
- **Versions read the way a person reads them** — `2.0.0` is no longer newer than `2.0` (a phantom update), and `1.2.3-beta` is no longer newer than `1.2.3`.
- **Major-upgrade note** — a paid or licensed app about to jump a major version gets one quiet line: the current license may not cover it.
- **GitHub's own mark** on GitHub links and the GitHub update button.
- **The site says it needs a model** — a reader pointed out that nowhere but GitHub mentioned Ollama or a key. He was right.

## The story (how 1.12.0 came together)

<!-- SF Symbol: book -->
"I tested it now, it's insane. What can we take from it to Sift?" One morning:
read the other project's source, pick the ideas that fit an auditor, build them
small. Testing against my real Applications folder did the rest — it found the
phantom `2.0.0` update in Sift's own comparator, showed that the first GitHub
design would hit the API limit with a shelf full of links, and proved the
redirect trick with thirty live checks in two seconds. Then the button I had
wanted all along — open the app, let it update itself.
