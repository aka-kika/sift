## What happened

<!-- SF Symbol: bandage -->
1.12.0 crashed about fourteen seconds after launch on my own Mac. Two installed
apps shared a bundle ID — `Reed.app` and `Reed Test.app` — and one had a saved
GitHub link. 1.12.0 widened the update check to GitHub-linked apps, which put
that pair into one batch for the first time; the refresh keyed a lookup by
bundle ID with `Dictionary(uniqueKeysWithValues:)`, and Swift traps on a
duplicate key.

If 1.12.0 crashes before it can update itself, download 1.12.1 from the site and
drag it over the old copy. Data and license keys are untouched.

## What shipped in 1.12.1

<!-- SF Symbol: shippingbox -->
- **No crash on duplicate bundle IDs** — the lookups keep the first value instead of trapping.
- **A regression test** that reproduces the exact crash (`Duplicate values for key`) before the fix and passes after.
- Everything from [1.12.0](https://github.com/aka-kika/sift/releases/tag/v1.12.0): GitHub releases as an update source, "Built with", open app to update, build-number updates, the version comparator.

## What I learned

<!-- SF Symbol: lightbulb -->
The side-build I tested 1.12.0 in had empty data, so it never met the duplicate.
1.12.1 was run as the real build against the real data before anything was
published. That check is part of the release from now on.
